# Ferrum — подсистема 2: оболочка редактора

Это спека подсистемы 2 из таблицы раздела 1 спеки ядра (`2026-10-23-ferrum-core-design.md`). Архитектура, потоки, протокол, хранение, ошибки и тесты устроены так, как написано в спеке ядра. Здесь описано только новое. Разделы ядра упоминаются как «ядро §N», разделы подсистемы 3 — как «векторы §N».

## 1. Цели

Пользователь может:
- открыть главное меню, как в Figma, с подменю «Файл», «Правка», «Вид», «Объект», «Текст», «Расставить», «Вектор», «Настройки» и «Справка». Недоступные пункты в нём серые, переключатели отмечены галочкой, у пунктов видны действующие сочетания клавиш;
- открыть контекстное меню на холсте, в слоях и в страницах. Пункты меню зависят от того, что выделено и по чему щёлкнули;
- найти и выполнить любую команду, найти слой на странице или повторить недавнее действие в «Быстрых действиях» (Ctrl/Cmd+K и Ctrl/Cmd+/), не трогая мышь;
- посмотреть все сочетания клавиш в панели «Сочетания клавиш» (Ctrl+Shift+?);
- копировать и вставлять свойства (Ctrl+Alt+C / Ctrl+Alt+V), вставлять с заменой (Ctrl+Shift+R), вставлять поверх выделения (Ctrl+Shift+V). Дубликат повторяет последний сдвиг, повторная вставка идёт со смещением;
- включить линейки (Shift+R) и тянуть из них направляющие; к направляющим работает привязка;
- сворачивать секции панели свойств, прятать боковые панели, отменять действие прямо из уведомления, переставлять и дублировать страницы.

**Не входит:**
- меню плагинов и сами плагины (подсистема 6);
- комментарии, «Поделиться», прототип (подсистемы 4 и 6);
- родное меню десктопа (бэклог B-50, отдельно);
- миникарта, её в Figma нет;
- сетки раскладки (layout grids) — подсистема 5 вместе с auto layout.

## 3. Команды: описание и состояние (ядро §7.6)

- **Описание команд.** Таблица `COMMANDS` в `ferrum-editor` получает поля:
  - `group` — группа меню. Сейчас она выводится из префикса ключа, теперь хранится явно;
  - `keywords` — русские и английские синонимы для поиска, например «дубль, duplicate, копия»;
  - `toggle` — признак переключателя.

  Названия остаются на русском. Без новых полей ничего не собирается: это проверяет тест на заполненность.
- **Команды интерфейса.** Действия, которые выполняет основной поток («Открыть…», «Сохранить на диск…», «Настройки…», «Сочетания клавиш», «Новый файл»), тоже лежат в таблице, с ключами `ui.*`. Ядро только сообщает о них: событие `UiCommand { key }`, и интерфейс выполняет действие сам. Благодаря этому меню, палитра и сочетания клавиш используют одну таблицу (ядро §7.6: «меню интерфейса вызывают команды по ID»).
- **Состояние команд.** Ядро считает для каждой команды, доступна ли она и отмечена ли:
  - `enabled` — есть ли что копировать, можно ли разгруппировать, есть ли что отменить, документ не только для чтения и т. д.;
  - `checked` — у переключателей: пиксельная сетка, линейки, «Текст кривыми», видимость интерфейса и т. д.
  
  Состояние приходит событием `CommandStates { changed: [{ key, enabled, checked? }] }` — только изменившиеся команды и только после шага, который мог их изменить: выделение, сцена, история, «только чтение», режим правки, настройки. Инструмент и вид в ключ не входят — ни одно состояние от них пока не зависит; новая зависимость состояния — новое поле `StatesKey`. Основной поток ничего не вычисляет, у него только таблица по ключу. Команда, которая недоступна, при вызове ничего не делает и не создаёт шага; так ядро и сейчас отвечает на сочетания клавиш.
- **Меню в ядре.** Главное меню и контекстные меню описаны данными в ядре: дерево `{ key } | { submenu, title, items } | separator`. Порядок и состав повторяют Figma UI3. Интерфейс получает дерево главного меню один раз (`MainMenu`), а контекстное — по запросу (§5). Интерфейс рисует меню и отправляет `Execute { key }`.
- **Сделано (этап 1):**
  - Таблица — 80 команд. Группа — перечисление `CommandGroup` (ключ и русское название: «Файл», «Правка», «Вид», «Объект», «Текст», «Расставить», «Вектор», «Настройки», «Справка» и для таблицы сочетаний — «Инструменты», «Сдвиг»); синонимы — строчные, хотя бы один русский и один английский; переключатели — четыре булевы операции, «Скрыть интерфейс», «Пиксельная сетка», «Привязка к пикселям» и три темы. Конструктор строки требует группу и синонимы; тест `command_table` проверяет заполненность, уникальность ключей и что ключ начинается с группы.
  - Команды `ui.*` (15): главное меню (Alt+/), новый файл, открыть, открыть с диска, сохранить на диск, копия на диск, экспорт (Ctrl/Cmd+Shift+E, как в Figma), все файлы, настройки, сочетания клавиш, о программе, привязка к пикселям (Ctrl/Cmd+Shift+', как «Snap to pixel grid»), три темы. «Сохранить» осталась `file.save` с прежним событием `SaveRequested`: её ключ — в сохранённых раскладках пользователей. Пункт меню команды `ui.*` основной поток выполняет сразу (выбор файла требует жеста пользователя); сочетание на холсте идёт через ядро и возвращается событием `UiCommand`. Правку вектора команды `ui.*` не заканчивают.
  - Для меню «Вид», «Текст» и «Вектор» добавлены команды ядра: «Пиксельная сетка» (Shift+', как в Figma), «Войти в правку» (`vector.edit`, Enter — физическая клавиша по-прежнему; удержанная клавиша в правку не входит), жирный, курсив, подчёркнутый, зачёркнутый (Ctrl/Cmd+B, I, U, Shift+X) и выравнивание (Ctrl/Cmd+Alt+L, T, R, J). Форматирование в правке текста идёт по действующей раскладке (раньше сочетания были зашиты), вне правки — ко всему тексту выделенных текстов одним шагом: жирный и курсив сохраняют семейство каждого участка.
  - Состояние считает `Editor::command_states` за один проход по выделению; пересчёт — по ключу (версия выделения, счётчик и эпоха сцены, история, «только чтение», правка текста и вектора, настройки) и не во время жеста; инструмент и вид в ключ не входят (тест `tool_and_view_do_not_change_states`). `CommandStates` в одной пачке событий ядра — одно событие (у команды — последнее состояние); первым — все команды (новое ядро, новый документ). Недоступная команда не выполняется в `Editor::run` — и с клавиатуры, и из меню: ни шага, ни сообщения.
  - **(поведение)** Как в Figma: булевы операции над одним слоем недоступны (раньше — сообщение «выделите хотя бы два слоя»); «Разгруппировать» доступна, только если выделен контейнер с детьми; в документе только для чтения недоступны правки (удалить, вставить, вырезать, дублировать, сгруппировать, сдвиг…), копирование и вид — доступны; инструменты доступны всегда (рисование в таком документе по-прежнему отвечает ошибкой). «Вставить» доступна всегда, кроме документа только для чтения: что лежит в системном буфере, ядро не знает. Вставка сочетанием (событие `paste` браузера, мимо `Editor::run`) подчиняется тому же состоянию: в документе только для чтения ядро молча отбрасывает `Paste`, `PasteImage` и `TextInput { paste }` вне правки текста, а интерфейс не читает буфер (без запроса разрешения и уведомлений).
  - Дерево — `ferrum_editor::main_menu()`; событие `MainMenu` уходит один раз при запуске ядра.

## 4. Главное меню (этап 1)

- **Где.** Кнопка с логотипом в левой панели, на месте нынешнего меню файла. Открывается щелчком и командой `ui.main_menu`, по умолчанию Alt+/ (в Figma — меню по логотипу и поиск в нём).
- **Подменю** **(поведение)**, состав как в Figma UI3 без плагинов, виджетов и Dev Mode:
  - «Файл»: новый, открыть, сохранить, сохранить на диск, копия, экспорт, все файлы.
  - «Правка»: отмена, повтор, копировать, вырезать, вставить, вставить поверх, вставить с заменой, копировать как PNG или SVG, копировать и вставить свойства, дублировать, удалить, выделить всё, выделить подобные (этап 2).
  - «Вид»: пиксельная сетка, линейки, показать или скрыть интерфейс, масштаб.
  - «Объект»: группа, фрейм, булевы операции, «Сплющить», «Контур обводки», отражение, скрыть, заблокировать.
  - «Текст»: жирный, курсив, подчёркнутый, выравнивание.
  - «Расставить»: порядок слоёв.
  - «Вектор»: войти в правку, перо.
  - «Настройки»: тема, пиксельная привязка, сочетания клавиш.
  - «Справка»: сочетания клавиш, о программе.
- **Компонент меню** (`menu.tsx`) получает:
  - подменю, которые открываются по стрелке вправо и по наведению с задержкой, как в Figma;
  - переход по первой букве;
  - галочку у отмеченных пунктов;
  - сочетание из действующей раскладки;
  - серые недоступные пункты. По ним можно ходить клавишами, но они не выполняются.
  
  Подменю держится на экране: у края окна оно отражается на другую сторону.
- **Поиск в меню.** Поле поиска вверху главного меню — тот же поиск, что в «Быстрых действиях» (§7), но только по командам.
- **Сделано (этап 1):**
  - **(поведение)** Кнопка с логотипом (оранжевый знак и стрелка) — слева в шапке левой панели; «Назад к файлам» переехала направо, на место прежней стрелки меню файла. Повторный щелчок по логотипу закрывает меню.
  - **(поведение)** Состав: «Файл» — новый, открыть, открыть с диска*, | сохранить, сохранить на диск*, копия на диск, | экспорт, | все файлы (* — только с File System Access или в десктопе, иначе пунктов нет); «Правка» — отменить, повторить, | копировать, вырезать, вставить, «Копировать как ▸» (PNG, SVG), | дублировать, удалить, | выделить всё; «Вид» — пиксельная сетка, | скрыть интерфейс, | приблизить, отдалить, 100 %, показать всё, показать выделение; «Объект» — сгруппировать, разгруппировать, обернуть во фрейм, | «Булевы операции ▸», сплющить, контур обводки, | отразить по горизонтали и вертикали, | скрыть или показать, заблокировать или разблокировать; «Текст» — жирный, курсив, подчёркнутый, зачёркнутый, | «Выравнивание ▸»; «Расставить» — на передний план, вперёд, назад, на задний план; «Вектор» — войти в правку, перо; «Настройки» — «Тема ▸» (светлая, тёмная, как в системе), привязка к пикселям, | сочетания клавиш, настройки…; «Справка» — сочетания клавиш, о программе. Вставка поверх и с заменой, свойства, «Выделить подобные», линейки — с их этапами.
  - **(поведение)** Открытие — фокус в поле поиска; стрелка вниз — к первому пункту, вверх с первого — обратно в поле. Подменю открывается наведением через 150 мс (наведение на пункт без подменю закрывает открытое через те же 150 мс; если фокус был внутри закрытого подменю, он возвращается в меню — на пункт-родитель), щелчком, Enter и стрелкой вправо; стрелка влево и Esc в подменю — к пункту-родителю, Esc в корне закрывает меню и возвращает фокус. Переход по первой букве — по кругу, без учёта регистра и «ё». Серые пункты фокусируются, но не выполняются и меню не закрывают. У подменю — стрелка «▸», у отмеченного — галочка, роль `menuitemcheckbox` у переключателей.
  - Подменю встаёт справа от пункта верхом вровень с ним; не влезает справа — слева от пункта, снизу — поднимается к краю окна (отступ 8 px). Положение считается в фазе `measure`; невидимое меню до этого стоит в углу окна, чтобы размер не зависел от места в потоке.
  - **(поведение)** Поиск этапа 1 — подстрока названия или синонима, без учёта регистра и «ё», в обеих раскладках (запрос переводится ЙЦУКЕН ↔ QWERTY); сначала команды, чьё название начинается с запроса, затем остальные в порядке меню; не больше 50; «Ничего не найдено» — строкой; Enter выполняет первую доступную. Нечёткий поиск с весами — этап 3.
  - **(поведение)** «Экспорт…» переводит фокус на кнопку секции «Экспорт» панели свойств (окна экспорта нет — B-96); «О программе» — уведомление; «Настройки…» и «Сочетания клавиш» открывают диалог настроек на вкладке «Горячие клавиши» (панель сочетаний — этап 3).

## 5. Контекстные меню (этап 2)

- **Запрос.** Интерфейс отправляет `ContextMenu { target: canvas { x, y } | layer { id } | page { id } }`. Ядро:
  - при щелчке по холсту сначала выполняет выбор, как Figma на правой кнопке: щелчок по невыделенному узлу выделяет его, по выделенному — сохраняет выделение;
  - отвечает событием `ContextMenu { items }` с уже вычисленным состоянием пунктов.

  Меню открывается у точки щелчка.
- **Холст** **(поведение)**, состав как в Figma, порядок блоков:
  1. Копировать, вставить, вставить поверх, вставить с заменой, «Копировать как» — подменю PNG и SVG.
  2. Копировать и вставить свойства.
  3. Выделить слой. Это подменю всех узлов под точкой щелчка, от верхнего к нижнему, как «Select layer» в Figma.
  4. Вперёд, назад, на передний план, на задний.
  5. Группа, разгруппировать, фрейм, булевы операции подменю, «Сплющить», «Контур обводки».
  6. Отразить, показать или скрыть, заблокировать или разблокировать.
  7. Только для текста: шрифт подменю недавних. Только для вектора: войти в правку.
  8. Удалить.
  
  На пустом месте — вставить, вставить поверх, выделить всё, показать всё, линейки.
- **Слои.** Те же пункты, что на холсте для этого узла, плюс «Переименовать» и «Развернуть всё» / «Свернуть всё». Правый щелчок по невыделенной строке выделяет её.
- **Страницы.** Переименовать, дублировать, удалить, «Копировать ссылку на страницу». Ссылка — `#/file/<id>?page=<pageId>`, маршрут её разбирает.
- **Сделано (этап 2):**
  - Дерево — `Editor::context_menu(ContextTarget)` (`context_menu.rs`); узлы дерева, кроме команд, подменю и разделителей, — `MenuNode::Node { id, name }` («Выделить слой», не больше 50, сверху вниз, у каждого попадания — оно и его контейнеры) и `MenuNode::Action { action, enabled }` — действие над целью меню, которое выполняет интерфейс (`MenuAction`: переименовать слой, развернуть и свернуть всё, переименовать, дублировать и удалить страницу, ссылка на страницу). Неизвестная цель, идущий жест — пустое меню (интерфейс его не открывает).
  - **(поведение)** Выбор на правой кнопке, как в Figma: узел, который выбрал бы щелчок (с правилами контекста и названием фрейма), выделяется, если не выделен; выделенный и пустое место внутри рамки выделения выделение сохраняют; пустое место вне её снимает выделение — меню пустого места. В правке текста и вектора правый щелчок правку не заканчивает.
  - **(поведение)** Холст: копировать, вставить, вставить поверх, вставить с заменой, «Копировать как ▸» (PNG, SVG) | копировать и вставить свойства | «Выделить слой ▸» | вперёд, назад, на передний план, на задний | сгруппировать, разгруппировать, обернуть во фрейм, «Булевы операции ▸», сплющить, контур обводки | отразить по горизонтали и вертикали, скрыть или показать, заблокировать или разблокировать | войти в правку (только у одного вектора или фигуры) | удалить. Недоступные — серые (состояние из `CommandStates`), а не скрыты. Пустое место — вставить, вставить поверх | выделить всё, показать всё. Подменю недавних шрифтов и линеек нет (B-120, B-121).
  - **(поведение)** Слой: невыделенная строка выделяется (как выбор из панели — без раскрытия и прокрутки); пункты холста без «Выделить слой», затем «Переименовать» (поле имени в строке), «Развернуть всё», «Свернуть всё» и «Удалить».
  - **(поведение)** Страница: «Переименовать», «Дублировать страницу», «Удалить страницу» (с подтверждением; единственную — серым), | «Копировать ссылку на страницу» (полный адрес, уведомление «Ссылка на страницу скопирована»). «Дублировать страницу» (незагруженную страницу с неизвестными узлами не дублирует: `DocError::ReadOnly`, копии нет) — копия с новыми идентификаторами и тем же фоном сразу после страницы, имя «<имя> (копия)», становится текущей; как и остальные операции со страницами, не шаг отмены (B-124). Ссылка открывает файл на этой странице (её нет — на первой) и оставляет в адресе только файл; неверный `page` (не `счётчик@узел` до 64 знаков) отбрасывается.
  - Интерфейс: правый щелчок шлёт `ContextMenu` (точка холста — `offsetX/Y`, без чтения раскладки), пункты приходят событием последними в пачке и встают в очередь планировщика вслед за выделением и состояниями команд; меню открывается у точки щелчка (длинное поднимается, чтобы влезть в окно). Локального меню холста больше нет.

## 6. Вставка и дубликат (этап 2)

- **Свойства.** «Копировать свойства» кладёт во внутренний буфер редактора и в системный буфер (`text/plain` с меткой Ferrum) заливки, обводки, стиль обводки, эффекты (когда появятся), прозрачность, режим наложения, скругление и стиль текста. «Вставить свойства» применяет к выделению то, что подходит его типу, одним шагом.
- **Вставить с заменой** (Ctrl/Cmd+Shift+R, как в Figma; страница перехватывает Ctrl/Cmd+Shift+R и на холсте, и вне его, перезагрузки нет; простое Ctrl/Cmd+R остаётся перезагрузкой браузера, поэтому настройки не предупреждают «Перехватывает браузер»; команда есть и в меню и палитре). Содержимое буфера встаёт на место каждого выделенного узла. Сохраняются позиция, родитель и место в слоях, как в Figma. Шаг один.
- **Вставить поверх** (Ctrl+Shift+V). Вставка на исходные координаты, без смещения к центру вида.
- **Повтор вставки.** Каждая следующая вставка того же содержимого сдвигается на +10, +10 от предыдущей, если исходный узел виден на экране; иначе — в центр вида, как сейчас.
- **Умный дубликат** **(поведение)**. После Ctrl/Cmd+D и сдвига копии следующий Ctrl/Cmd+D повторяет тот же сдвиг. Запомненный сдвиг сбрасывается при любом другом действии с выделением.
- **Выделить подобные.** Выделяются узлы того же типа с теми же заливками и обводками на странице. Работает в worker'е, на 100 000 узлах ≤ 100 мс.
- **Сделано (этап 2):**
  - Команды (группа «Правка», все пять в главном меню; в меню холста нет только `edit.select_similar`: он доступен сочетанием и из главного меню): `edit.paste_over` (Ctrl/Cmd+Shift+V), `edit.paste_replace` (Ctrl/Cmd+Shift+R — оба `browserKey` пропускают Mod+Shift+R до ядра, в `browser_reserved` добавлено простое `Mod+KeyR` (перезагрузка браузера), а `Mod+Shift+R` — нет, поэтому настройки не пишут «Перехватывает браузер»; проверено в Chromium и Firefox, Safari не проверен, B-125), `edit.copy_props` и `edit.paste_props` (Ctrl/Cmd+Alt+C и V), `edit.select_similar` (Ctrl/Cmd+Alt+A, как «Select matching layers»). Таблица — 85 команд.
  - **(поведение)** Вставка поверх — на исходные координаты в ту же цель, что у обычной вставки, без сдвига к центру и без шага повтора. Ctrl/Cmd+Shift+V на холсте приходит событием `paste` браузера с режимом «поверх»; в правке текста — по-прежнему обычный текст.
  - **(поведение)** Вставка с заменой — для каждого выделенного узла верхнего уровня, кроме заблокированных: содержимое буфера левым верхним углом рамки — в угол рамки узла, у того же родителя и на его месте в слоях, узел удаляется; выделены вставленные; один шаг. Выделения нет (сняли, пока читался буфер) — обычная вставка.
  - **(поведение)** Повтор вставки того же содержимого (хэш байтов), пока исходное видно и помещается в цель, — +10, +10 от прошлой вставки; иначе — в центр, как раньше. Новая копия начинает счёт заново (B-127).
  - **(поведение)** Свойства: копия — свойства первого выделенного (заливки, обводки и их стиль, прозрачность, скругление, у текста — стиль первого участка и его собственная заливка, если у него она своя); во внутренний буфер ядра и текстом `ferrum-props:v1:` + base64 формата буфера (один узел, с изображениями своих заливок) в `text/plain`; уведомление «Свойства скопированы». Вставка берёт копию свойств или копию узлов (свойства первого узла, как в Figma) из системного буфера, без доступа или без наших данных — внутренний буфер, без него — «Сначала скопируйте свойства». Каждому выделенному — что подходит типу: у группы и линии нет заливок, у группы — обводок, у группы и текста — стиля обводки, скругление — у фрейма, прямоугольника и изображения, стиль текста — тексту (рамка подгоняется); одним шагом; заливки, вставленные в текст, в том же шаге снимают собственные заливки его участков. В правке текста «Вставить свойства» недоступна. Копия свойств обычной вставкой не вставляется.
  - **(поведение)** Умный дубликат: пока выделены копии прошлого Ctrl/Cmd+D и выделение не менялось (их двигали протяжкой или стрелками, отменяли и повторяли сдвиг), новый дубликат сдвигается от них на тот же шаг, что они от своих оригиналов. Любое другое действие с выделением (выбор, отмена дубликата) шаг забывает.
  - **(поведение)** «Выделить подобные»: видимые и не заблокированные узлы страницы того же типа с теми же заливками и обводками, что у любого из выделенных (до 64 разных образцов); совпавший контейнер — без потомков; выбор — не шаг истории. На 100 000 узлах — 1,3 мс нативно (`editor_report`).
  - «Копировать как PNG» уже был (этап 5 подсистемы 3): событие `ClipboardPng`, теперь — в подменю «Копировать как» меню холста.

## 7. Быстрые действия (этап 3)

- **Открытие.** Ctrl/Cmd+K и Ctrl/Cmd+/, как в Figma. Esc закрывает, стрелки выбирают, Enter выполняет. Окно — поле поиска сверху по центру холста.
- **Источники**, в одном списке с заголовками:
  - недавние команды — последние 8, хранятся в настройках;
  - команды — название, синонимы, группа и сочетание; недоступные показаны серыми и не выполняются;
  - слои текущей страницы — по имени, переход к слою выделяет его и показывает в виде;
  - страницы.
- **Поиск.**
  - Нечёткий, по подпоследовательности с весом: начало слова, совпадение с синонимом, недавность.
  - Раскладка не важна: «щквук» находит «order», запрос переводится из одной раскладки в другую. (Прежний пример «ыщквук» — это «sorder»: лишняя первая буква.)
  - Регистр и буква «ё» не важны.
  - Команды ищутся в основном потоке (их ≈ 70). Слои ищет worker: `FindLayers { query, limit: 50 }` → `LayersFound`, на 100 000 узлах ≤ 30 мс на обычных именах и на каждом тёплом запросе; первый запрос после правки имён на 100 000 длинных имён — ≤ 40 мс (бюджет ниже). Каждый символ ввода сбрасывает предыдущий запрос.
- **Тонкий основной поток.** Список в окне — не больше 50 строк, без виртуализации; раскладка читается только в фазе `measure`.
- **Сделано (этап 3):**
  - Команда `ui.quick_actions` («Быстрые действия…», группа «Вид», Ctrl/Cmd+K и Ctrl/Cmd+/, конфликтов в раскладке нет) — команда интерфейса: сочетание на холсте идёт через ядро (`UiCommand`). В главном меню пункта нет (его поиск — поле вверху самого меню). Таблица — 86 команд.
  - Поиск — `crates/ferrum-editor/src/find.rs` (слои) и `apps/web/src/ui/fuzzy.ts` (команды, страницы) с одними правилами: буквы запроса встречаются в тексте по порядку; вес — совпадение 1, начало слова +8, буква сразу за прошлой +5, иначе минус пропуск (не больше 3), начало текста +6, иначе минус сдвиг (не больше 3), весь текст без пробелов +10; пробелы запроса не учитываются. Общие векторы весов проверяют Rust и TS одинаково. Команда: лучшее из названия и синонимов (синоним −4), недавняя +3 за каждое место до восьмого (`palette.ts`). Поиск главного меню — тот же нечёткий (раздел 4, этап 1 — подстрока): только по командам дерева меню, без недавности.
  - **(поведение)** В поиске участвуют первые 40 символов имени (`FIND_NAME_CHARS` в ядре, тот же предел `MAX_TEXT_CHARS` у команд и страниц в `fuzzy.ts`). Совпадение дальше 40-го символа не находится. От запроса тоже берутся первые 40 символов вместе с пробелами: вставленное целиком длинное имя находится по началу. Показывается имя целиком, до 256 символов. Цена предела: хвосты имён-путей вида «Button / Primary / Large / Hover / With icon» не ищутся (B-150). На 48 и 64 символах первый запрос после правки имён выходил за 30 мс или вплотную к ним.
  - Бюджет поиска слоёв, 100 000 узлов (нативно, release): ≤ 30 мс на обычных именах (холодный и тёплый) и на каждом тёплом запросе; первый запрос после правки имён на длинных именах (40 и 256 символов, «я» × 256, немецкий, украинский, китайский) и первый на странице — ≤ 40 мс; синтетика «две раскладки» (три варианта запроса подходят к каждому имени) — ≤ 45 мс. Отсев: маска букв и верхняя граница веса против порога лучших `limit`; сборка индекса — таблица свёртки регистра на символы до U+07FF и диапазоны букв без регистра. Холодный запрос равен сборке индекса плюс поиск: на длинных именах 27,7–38,9 мс (сборка около 20–31 мс плюс поиск около 8 мс), зависит от загрузки машины; запас небольшой, а вернее держать его обновлением индекса по изменённым узлам (B-150).
  - **(поведение)** Пустой запрос: «Недавние» (если есть) и «Команды» в порядке таблицы. Запрос: «Команды» (до 20), «Слои» (из worker'а, сколько влезет), «Страницы» (до 10); строк с действиями — не больше 50, пустые разделы без заголовков. В палитре нет удержания руки, Esc, сдвигов и самой палитры; команды файла на диске без File System Access — тоже нет.
  - **(поведение)** «Слои» не показывают строки прежнего запроса: новый запрос сразу убирает их, пока ответ на него не пришёл, и Enter к ним не переходит. «Ничего не найдено» появляется только после ответа worker'а (если команд и страниц тоже нет).
  - **(поведение)** Строка команды: галочка у отмеченного переключателя, название, группа, первое сочетание; недоступная серая, по ней можно пройти стрелками, Enter и щелчок её не выполняют и палитру не закрывают. Новый список — выбрана первая доступная; выбор стрелками хранится за строкой (тип и ключ или `id`) и не сбрасывается поздним `LayersFound` на тот же запрос, пока строка есть. Стрелки — по кругу; щелчок — как Enter; Esc и то же сочетание — закрыть с возвратом фокуса; щелчок мимо и Tab — закрыть без возврата. Команда выполняется, как из главного меню (`ed.run`, `ui.*` — сразу, из жеста пользователя).
  - **(поведение)** Ввод: Enter и Esc при составлении текста (IME) не выполняют и не закрывают окно. Щелчок внутри окна оставляет фокус в поле (Delete не удаляет выделение, Esc и сочетание закрывают); если фокус всё же ушёл, Esc и сочетание палитры закрывают её, а остальные клавиши до холста не доходят. Удержание Enter выполняет команду один раз; удержание Ctrl/Cmd+K, Ctrl/Cmd+/ или Ctrl+Shift+? окно не мигает (повтор клавиши проглатывается).
  - **(поведение)** Ctrl/Cmd+K открывает палитру и из полей панелей (действие Ctrl+K браузера подавлено); в модальных диалогах и в элементах с ролью `dialog` или `menu` — нет (B-143).
  - Недавние — последние 8 команд, выполненных из палитры и из меню (главного и контекстного), новые первыми; хранятся в настройках (`recentCommands` — ключи через пробел; общие для вкладок; файл настроек десктопа — то же поле). Сочетания и кнопки панелей в недавние не попадают: инструмент на клавише вытеснил бы всё остальное (B-140).
  - **(поведение)** Слой: строка — иконка типа и имя. Выбор — `RevealLayer`: слой выделяется, предки раскрываются, панель слоёв прокручивается к строке — и когда слой уже выделен; вид: виден целиком — прежний, влезает при нынешнем масштабе — центр на слое, не влезает — вписан с отступом, как «Показать выделение». Слой, которого не видно (скрыт сам или лежит в скрытом фрейме), — только выделение, камера не двигается. Страница: `SetPage`.
  - Палитра — внутри холста (`.fe-stage`), положение задаёт CSS, чтений раскладки нет, кроме прокрутки выбранной строки (в `measure`). Ответы `LayersFound` — через очередь планировщика; ответ не на последний запрос отбрасывается по `query`. Запрос обрезается до 256 байт по границе символа (интерфейс), ядро ищет по первым 40 символам.

## 8. Панель сочетаний клавиш (этап 3)

- Ctrl+Shift+? и пункт «Справка → Сочетания клавиш». Внизу окна поднимается панель, как в Figma: вкладки по группам, у каждой команды — клавиши из действующей раскладки, а уже использованные недавно отмечены. Есть ссылка «Изменить в настройках».
- Данные — те же `KeymapEntry`, что у вкладки «Сочетания» в настройках. Новых данных в протоколе нет.
- **Сделано (этап 3):**
  - `ui.shortcuts` получила Ctrl+Shift+? (`Ctrl+Shift+Slash` — Ctrl и на маке, как в справке Figma; физическая клавиша — та, где «/» в раскладке US, подпись — `⌃⇧/`, B-144). «Справка → Сочетания клавиш» и «Настройки → Сочетания клавиш» открывают панель, а не настройки (этап 1).
  - **(поведение)** Панель — на всю ширину окна, у нижнего края, высота 320 px (не больше половины окна), поднимается за 160 мс. Заголовок, вкладки в порядке вкладки настроек, ссылка «Изменить в настройках» (панель закрывается, настройки открываются на вкладке «Горячие клавиши»), кнопка закрытия. У команды — все клавиши действующей раскладки подписями под раскладку пользователя; без сочетания — прочерк (команда остаётся в списке).
  - **(поведение)** Окно не модальное, как в Figma: холст работает под панелью. Фокус при открытии — на выбранной вкладке, стрелки, Home и End — по вкладкам. Esc (фокус в панели) и то же сочетание (из панели и с холста) закрывают; фокус возвращается, только если он был в панели. Удержание сочетания панель не мигает.
  - **(поведение)** Отмечены (точка у названия и цвет клавиш) команды из недавних палитры и вызванные сочетанием за этот сеанс — включая Ctrl/Cmd+C, X и V. Сочетание сопоставляется с действующей раскладкой в основном потоке (без новых данных в протоколе): отметка — о нажатии, а не о том, что сделало ядро; сочетания сеанса не сохраняются (B-141).

## 9. Линейки и направляющие (этап 4)

- **Линейки** (Shift+R, «Вид → Линейки»).
  - Сверху и слева от холста, деления в единицах мира под масштаб. Выделение подсвечено на линейке полосой. Начало отсчёта — фрейм верхнего уровня под выделением, иначе ноль страницы.
  - Рисует их ядро в том же кадре, что и холст, отдельным слоем оверлея.
  - Включены ли линейки — настройка вида; она сохраняется.
- **Направляющие.**
  - Протяжка из линейки создаёт направляющую. Она принадлежит фрейму верхнего уровня под курсором, иначе странице. Направляющую можно тянуть; утащенная обратно на линейку удаляется.
  - Модель: ключ `guides` у страницы и фрейма — список `{ axis: x | y, offset }`, до 1000 штук на узел. Неверные данные из файла проверяются как в ядре §4.3.
  - Каждая правка направляющих — шаг отмены.
  - Привязка: к направляющим, как к краям узлов, 4 экранных пикселя (ядро §7.3).
  - Показ и скрытие направляющих — пункт «Вид → Направляющие» и сочетание из справки Figma. Точное сочетание сверяется со справкой Figma в плане этапа 4 и проверяется на конфликт с раскладкой.
- **Совместимость.** Файл с направляющими открывается старой сборкой как обычно: неизвестный ключ просто не читается. Проверка — `scripts/compat-old-build.sh <ref> guides_fixture`.

## 10. Полировка панелей (этап 4)

- **Сворачиваемые секции.** Заголовок каждой секции панели свойств сворачивает её. Свёрнутость хранится в настройках по имени секции.
- **Скрытие панелей.**
  - Ctrl+\ прячет весь интерфейс, это уже есть.
  - Левую панель можно свернуть кнопкой в её заголовке, как в Figma UI3.
  - Ширина и свёрнутость каждой панели запоминаются.
- **Уведомления с действием.**
  - У уведомления может быть кнопка «Отменить». Её получают удаление, «Сплющить», «Контур обводки», разгруппировка и вставка с заменой; кнопка вызывает `edit.undo`, если шаг ещё последний.
  - У каждого уведомления есть кнопка закрытия.
  - Уведомление живёт 4 с; пока над ним курсор, оно не исчезает.
- **Страницы.** Перестановка протяжкой в списке и «Дублировать страницу» — одним шагом каждая.
- **Имя текстового слоя** **(поведение)**, как в Figma: новый текст называется своим содержимым, первые 40 символов первой строки, пока имя не переименовали вручную. Закрывает бэклог B-28.

## 11. Протокол (дополнения к ядру §4.3)

- **Команды:**
  - `ContextMenu { target }`;
  - `FindLayers { query, limit }`;
  - `RevealLayer { id }`;
  - `SetGuides { owner, guides, phase }` (протяжка — превью, отпускание — шаг);
  - `SetView { rulers?, guides? }`.
- **События:**
  - `MainMenu { tree }`;
  - `CommandStates { changed }`;
  - `ContextMenu { items }`;
  - `LayersFound { query, items }`;
  - `UiCommand { key }`.
- **Пределы:**
  - `query` — не больше 256 байт;
  - `limit` — не больше 200;
  - направляющих — не больше 1000 на узел;
  - `offset` — конечное число, по модулю не больше 1e9;
  - ключи меню — только из таблицы.
- **Сделано (этап 1):**
  - `MainMenu { tree }`, где `tree` — `MenuItemDto[]`: `{ type: "command", key } | { type: "submenu", title, items } | { type: "separator" }` (тег `type`, как у остальных событий).
  - `CommandStates { changed: [{ key, enabled, checked? }] }`; `UiCommand { key }`.
  - `SetTheme` получил необязательный `system` — тема выбрана «как в системе» (для отметки «Тема как в системе»).
  - `KeymapEntry` получил `keywords` и `toggle`, а `group` теперь — группа из таблицы, а не префикс ключа.
- **Сделано (этап 2):**
  - `ContextMenu { target }`, `target` — `{ kind: "canvas", x, y } | { kind: "layer", id } | { kind: "page", id }` (лишние поля и неизвестный вид — ошибка разбора; нечисловая точка и неверный формат id — `Error` и пустое меню; верный по формату id, которого уже нет (строку успели удалить), — пустое меню без `Error`). Ответ — `ContextMenu { items }`: `MenuItemDto` получил `{ type: "node", id, name }` и `{ type: "action", action, title, enabled }` (`action` — `renameLayer | expandAll | collapseAll | renamePage | duplicatePage | deletePage | copyPageLink`); ключи команд — только из таблицы.
  - `ExpandAllLayers { expanded }`, `DuplicatePage { id }`.
  - `Paste { bytes, mode? }` и `PasteRequested { mode }`, `mode` — `normal | over | replace | props`; на `props` интерфейс отвечает `PasteProps { bytes? | text? }` (байты `web application/x-ferrum` или текст с меткой свойств или узлов; без них — внутренний буфер; текст — не длиннее предела текста буфера). `ClipboardProps { text }` — копия свойств для `text/plain`. Сообщение worker'у `pasteText` несёт `mode`.
- **Сделано (этап 3):**
  - `FindLayers { query, limit }` → `LayersFound { query, items }`, `items` — `[{ id, name, kind }]` (имя — не длиннее 256 символов, `kind` — как у строки панели слоёв; лучшие первыми, при равном весе — в порядке панели). `query` длиннее 256 байт — `Error` без ответа; в поиске участвуют первые 40 символов запроса и имени; `limit` больше 200 — урезается; пустой запрос — пустой ответ. Шрифтов не ждёт: документ не меняет. Отмены выполняющегося поиска нет: команды worker'а идут по очереди, интерфейс отбрасывает устаревший ответ.
  - `RevealLayer { id }`: неверный формат — `Error`, слоя нет на текущей странице — `Error`; выбор — как с холста (предки раскрываются, панель прокручивается — и у уже выделенного слоя), не шаг истории; у слоя, которого не видно (скрыт или лежит в скрытом фрейме), камера не двигается.

## 12. Тестирование

Как в ядре §12:
- **Модульные тесты ядра:**
  - заполненность таблицы команд;
  - состояние `enabled` и `checked` для каждой группы ситуаций;
  - состав контекстного меню для каждого вида выделения;
  - вставка с заменой и поверх, умный дубликат, копирование свойств;
  - направляющие в документе, отмена и привязка;
  - поиск слоёв.
- **Замеры:**
  - `CommandStates` после шага на 100 000 узлах — ≤ 1 мс;
  - поиск слоёв — ≤ 30 мс (обычные имена и тёплые запросы), ≤ 40 мс первый запрос после правки на 100 000 длинных имён;
  - «Выделить подобные» — ≤ 100 мс;
  - кадр с линейками — не больше кадра без них плюс 0,5 мс.
